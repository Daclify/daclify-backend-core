# Local community MCP pairing — M2

Implementation in the isolated feature worktrees. No production deployment, live account deletion, native owner/active changes or real asset movement. Source execution continues with M3.

Local pairing creates a five-minute public-key/PKCE request for an exact DAO/member and bounded routine or app scopes. The trusted browser retains the single account kit, signs the native delegate, and approves the exact body using the existing fresh account-control proof. The local process redeems once, encrypts its replaceable delegate/token in a 0600 file under a 0700 directory, and prints command/args/credential-reference configuration. The account root is not exported. Trusted-terminal confirmation and explicitly selected autonomous operation are distinct. Background/IDE hosts without a trusted terminal require a later qualified host secret store; universal harness signing is not claimed.

The shared producer `prepareCommunityInstruction` serves Node and internal service principals. Local access does not fake a root login or pass a scoped bearer into ordinary API routes. It rechecks current native membership, nonce, session/epoch/expiry, guardian, reviewer, policy, deployment and app binding. Before sending, the service persists the exact signed relayer transaction, then validates current preparation again. Unknown delivery reconciles the same ID through bounded irreversible-block scans and freezes other preparations. Exit packets and scoped packets use separate purpose checks; the existing exit scope remains unchanged.

046_mcp_pairing.sql SHA256 **bb5bf06ba550e32f6ee2da83b5321c0adf537ebd9de4496d4c9849ce5c90eed9** is frozen. Requests/grant/preparation JSON and packets are bounded. Five-minute requests have global admission and IP bounds; redeem polling uses its separate bounded allowance. Stored token hashes are 32 bytes. At most 16 live preparations and one uncertain submission per grant; expiry/owner/grant indexes serve bounded lookups and cleanup. Parent cleanup waits for referenced records to be removed, avoiding unbounded cascade work. The account inventory classifies all three tables, and shared reconnect deletes both owners' consent/preparation/grant records before retiring ownership. SQL reconnection revokes hosted consent; independently copied native delegate keys retain native epoch/expiry/revocation rules until the member retires the session.
