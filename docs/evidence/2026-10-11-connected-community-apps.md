# Connected community apps qualification — 2026-10-11

Core/frontend `0.13.0-alpha.6` and modules SDK `0.9.0-alpha.22` combine connected apps with quick signup and assisted-recovery opt-out, installed on public testnet. Machine-readable source/archive pins, irreversible deployment transactions, measurements and test counts are in [the evidence record](2026-10-11-connected-community-apps.json).

The additive runtime registry and app-session constraints preserve existing serialized member/session/document records. Native Activity records opaque source/revision/event commitments and optional protected evidence references. App delegates can record or request review; independent review, app administration, key grants and DAO decisions use the existing trusted signer. Membership, app revision, credential epoch and current code pins are checked afresh. Tokens/subjects are per app; no private pairings or root keys are exported.

The five existing module alpha.5 WASM/ABI releases are retained. Rebuilding their current sources with `-O=s` reproduced the previous RAM audit's separate size candidates; those candidates are not promoted or deployed in this additive rollout. Activity is compiled with pinned CDT 4.1.1 `-O=s`.

Final core qualification passed 139 files/872 tests, modules 30 files/179 tests, and frontend 42 files/275 tests with its testnet build. Combined PostgreSQL passed 55 checks. The seven owned Spring cases cover two apps/seven members, public/private DAOs, actual session/receipt/key readers and actual delegated API relay, isolated authority, independent review, exact-revision ballot links, offboarding/key rotation and runtime-delegated module control. Native permission-tree qualification passed 32 cases. Combined desktop/mobile browser tests passed 52 cases for account entry, signup, recovery opt-out and connected apps.

Three native upgrade transactions are irreversible. Frozen verification preserved pre-existing rows, balances, owner/active authorities, links and all five previous module pins. Legacy Hub metadata was preserved verbatim while its code/ABI pins were updated. The new keyless Activity account delegates control to the existing runtime; its RAM quota immediately after installation was 4,195,701 bytes with 1,876,403 used. The API/frontend and Names updater use archived matching source; issuer keys and recovery configuration survived the final API cutover.

An owned synthetic public DAO has seven members, two managers and two independently registered apps. Actual public HTTPS consent/code/token flows and member-approved native signing grants recorded one completion per app as member 3. Both explicit no-snapshot epochs were accepted. Repeating each frozen event returned its original receipt, without another record. This used the real SDK and native-backed public API; it did not deploy your friend's app or an external browser callback page.

The public run exposed a transport validation bug that direct gateway tests had missed: decoded native wrapper objects and safe uint64 numbers did not match action schemas. Both HTTP activity actions reproduced the failure. Canonical objectification and lossless decimal conversion fixed it while preserving exact-byte round-trip and app/DAO/member checks. The actual database tests verify accepted wire requests and cross-app rejection; the patched API is archived at core commit `a8272d4`. The public SDK archives and native binaries remain unchanged by that API-only fix.

Actual native measurements include table/index overhead: Activity WASM 187,031 bytes, first app receipt/count/headers 1,225 physical RAM bytes and second app receipt/count 889 bytes. Action CPU is recorded in the JSON from the owned fixture; it is not public testnet timing. Native capacity is bounded at 64 registrations/DAO, 16 member sessions, seven-day grants, 25-row cleanup, 10,000 receipts/app and 128 key epochs/app. Projects retain detailed task state separately. Permanent audit/evidence references are not pruned automatically.

The working [SQLite/outbox example](../../examples/community-mini-app/README.md) preserves a completing member and exact event across restart/retry, freezes optional snapshot commitments, and applies reviews only to the still-current submitted source revision. Daclify encrypts selected manifests and file bytes inside its trusted vault boundary. The project pins ciphertext with its own provider credential. Snapshot grants remain separate from recording credentials; integrity, app/source/event domain and native key commitment are checked before decryption.

Review was performed inline because workspace instructions prohibit delegation. Significant findings produced actual failing regressions: stale consent revision, zero key commitments, orphan epochs, outdated future keys, expired credentials occupying slots, offboarding grants, unsorted native authority weights and a native account-name/uint64 session-reader mismatch. The remaining provider/independent-host qualifications are explicit in the JSON. Real email/Telegram user ceremonies and live project IPFS uploads were not repeated. The separate Docker research module-integration suite was unavailable; its attempted run is not a passing check.

Public testnet assisted signup is enabled with the user-authorised [single-VM development recovery setup](2026-10-11-testnet-single-host-recovery.md). The actual local snapshot restore and public synthetic signup used OpenBao and encrypted Pinata recovery storage. This is not independent-host qualification: the UI warns before consent, mainnet rejects this mode, and the current report expires on 17 October 2026. Mainnet requires the independent topology and source-loss evidence in [the recovery runbook](../../ops/recovery/README.md). Real email/Telegram user ceremonies, wallet/passkey private unlocks and live project snapshot uploads remain unqualified. No mainnet deployment occurred.
