# Unified Users verification

Source implementation is complete; the new testnet rollout has not been approved or broadcast. The [design](../superpowers/specs/2026-10-11-unified-users-design.md), [execution plan](../superpowers/plans/2026-10-11-unified-users.md), [upgrade runbook](../operations/unified-users.md) and [machine-readable evidence](2026-10-11-unified-users.json) describe the scope and exact artifact pins.

The directory combines public memberships using native accounts/current signing-key fingerprints and displays published profile data, avatars, safe contact links, all loaded DAO links and latest successful member instructions. It keeps private sign-in pairings out of public grouping. User details preserve individual profile ownership and expose other proven memberships. Automatic bounded paging, stale-response rejection, retry, cards/list, avatar fallback and independent operator scoping are preserved.

The separate metered `memberacts` table preserves the original member layout. New enrollment and bounded executive-authorized legacy initialization reserve zero-time rows. All authenticated dispatch paths update existing rows only; failed/replayed requests roll back or preserve activity. Real signed native tests cover K1/native/R1 sessions/EVM, installed modules, wrong signers, changed EIP-712 data, partial executive quorum, actual legacy upgrades and unchanged physical RAM on timestamp updates.

Final optimized checks passed: core 829 tests in 132 files; modules 164 in 28; frontend 217 in 39; native permissions/workflows/activity/legacy 146 in 10. Twelve browser journeys passed on desktop and Pixel 7 (24 runs), including accessibility and overflow assertions. All three builds passed; frontend was built in testnet mode into a review artifact, without publishing or restarting services. Format and generated-reference checks passed. Core verification correctly refused unqualified immutable publication.

An initial browser regression caught signed-out links incorrectly pointing to `/users/me`; a guarded ownership condition and explicit route assertion fixed it. A detail regression now preserves the proven public account name for an unpaired membership without a profile. A public-projection overlap regression preserves maximum observed activity when exact lookups and directory pages overlap. A preexisting crypto test's one-second polling deadline was replaced with a deferred API-boundary notification, retaining actual cryptography and its account-change/CSRF checks.

The workspace adopted CDT `-O=s` during execution. Its build-policy commits are core `b2b3bce` and modules `ea32ad9`; the Users runtime was rebuilt and requalified accordingly. The candidate is 869,764 WASM bytes (14.66% below the initial unoptimized Users candidate). Its seven-action readonly testnet simulation executed in 27,693 μs CPU / 27,205 NET words and freed 1,431,041 net root RAM bytes. No RAM purchase or token transfer remains in the current proposal. Simulation bypasses signature and minimum-permission checks; real native pushes establish the separate permission evidence.

Readonly live projection found four memberships grouped into three current public identities: the native governing member, a shared signing identity in two smoke DAOs, and the separate qualification member. None has a published profile or an ordinary-member activity timestamp. Missing avatars/contact fields and historical dates remain absent rather than invented.

No Hub-wide identity registry, private service-account correlation, historical action reconstruction or module contract redeployment was introduced. Different unlinked keys may still produce separate cards. SQL migrations and live provider writes were unaffected and their suites were not repeated. The public API/frontend/oracle stay on the previous approved release until the new concrete rollout is approved.
