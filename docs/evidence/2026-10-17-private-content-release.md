# Maximum content privacy testnet release

Core/SDK 46, modules 57 (native 10), frontend 65 and community MCP 23 are live on shared testnet. All 11 native stages are irreversible and the public portal/API checks pass. See [machine-readable results](2026-10-17-private-content-release.json) and the [signed migration guide](../private-content-migration.md).

Encrypted DAOs protect identity text, ordinary ballot wording and option labels, payroll names, agent descriptions and existing document-based narratives. Creation orders and claim invitations carry sealed descriptions. Private content stays in browser memory after verification; lock, sign-out and context changes clear it. Hosted MCP and documentation assistants receive no automatically decrypted content. Decrypted file exports require an explicit unprotected-copy action.

Final full unit runs passed: core 1,141, modules 309, frontend 463 and the independent MCP package 13. Separate deployment checks passed 5. All 27 native Quick cases passed, including 5,000 authorized votes. Actual native upgrade/rollback preserved runtime rows, original keys, an open ordinary ballot and approved payroll terms. The measured native contract RAM increase matches code bytes×10 plus ABI growth. Source-only browser checks passed 10 across desktop/mobile. All 40 compiled desktop/mobile cases have green evidence: 38 passed together, then the two failures passed in focused follow-ups. The full run had a stale unlock-navigation helper and one transient owned-node error. All 12 real-provider cases passed across 9 initial and 3 focused passes; their eight-file fixture budget required splitting the run. Pinata upload, gateway retrieval and removal of 12 synthetic provider files were verified (55,916 bytes uploaded; 178,620 retrieved). The final source reproduces all 158 compiled candidate files byte-for-byte.

The exact released source and ABI layouts are preserved for archives. Existing ordinary ballot definitions and Quick protocol 1 keep their original interpretation. The MCP correction permits `openpoll`/`votecommit` only within the requested scope and exact installed module/session grants. Old delegates are never widened automatically.

## Release gates and rollback

The cutover snapshot covers 11 contract accounts, 11 DAOs, two open ordinary ballots and three historical Quick ballots. It contains no pending claims/reserves or frozen financial targets. Every stage checked code/ABI hashes, all captured raw rows and scopes, keys, authority parents/thresholds, exact action routes, available signing authority, packed transaction bounds and native simulation. Raw permission metadata is required; wildcard routes are refused. Unknown state stops the rollout.

The authorized RAM purchase cost **53.8281 testnet TLOS**, below the 60 TLOS cap, from `3boidanimus3`. Five contracts received 937,969 bytes from a 916 KiB request; native purchase rounding accounts for the 15-byte difference. Every actual quota exceeds code/ABI growth plus the 64 KiB deployment reserve. The purchase is irreversible and was not repeated after the strict requested-byte postcheck flagged that rounding. Contract growth remains separate from existing DAO grants and completion capacity.

The rollout adds nine missing action routes to the existing `execctx` permission: `setagentdesc`, payroll `commitpriv`/`editpriv`, and six existing recovery actions. It creates no permission and changes no signing key, authority parent or threshold. The native round-trip installs, removes and reinstalls these exact routes; unit checks reject unrelated routing or authority changes.

The previous immutable API, frontend, public packages, raw ABI/code, database backup and forward/reverse plan are retained. The old API/workers were stopped during the shared-contract transition. The fresh database backup was restored into an isolated PostgreSQL instance, and candidate migrations preserved all original rows/columns across 99 existing tables. The frontend/API switched together after private qualification. Appjoin stays disabled because this operator has no configured deployment.

`tools/deploy/private-content-testnet.ts --prepare <protected-snapshot>` prepares the fixed reviewed cohort without broadcasting. `--apply`, `--verify` and `--rollback` use that same plan. A receipt journal permits only a confirmed forward prefix or rollback suffix. Every broadcast requires a successful simulation without asset transfers and a final irreversible receipt. A rollback refuses unexpected rows, permissions or source changes; customer writes after activation require a new compatibility review rather than blindly installing an old binary.

Native authorization checks `unlinkauth` before any action executes, so a single rehearsal cannot create and remove an absent link. Preparation simulates link creation; the deployed link stage then simulates its reverse before directory admission. The owned native round-trip also reproduces that rejection and verifies separate installation, reversal and reinstallation.

Module document-source scans retain their old identity until bounded `backfillrefs` or a supported source operation registers the current source. Stale coverage prevents pruning. Do not bypass that protection or convert customer descriptions during index maintenance. Review any such maintenance as a separate rollback boundary.

TESTDAO-2's nine original rows were checked after deployment: content, epochs, key grants, original keys, policy and roles are preserved; two technical module-code pins changed as planned. Its owner's signed content-upgrade preview remains required.

An owned synthetic self-custody account created one DAO on actual Telos testnet. Its interrupted private setup resumed with the original kit, and it published/read encrypted identity and ordinary ballot wording and cast a signed vote. After a real API restart, a fresh browser restored the same signing/encryption keys and decrypted the same records. Locking removed private content and an anonymous browser could not read it. Canary scans passed across 99 public database tables and the API journal. Custody tables were not scanned for this self-custody fixture. Public account/DAO/Quick ballot/mini-app pages passed on desktop and mobile without page errors; exact compiled assets, retained old chunks, CORS/session metadata, OAuth discovery and authenticated MCP tool-call boundaries passed.

Startup was held until a fresh disposable TLS/OpenBao 2.7.1 Raft source-removal restore qualified core 46: original synthetic key recovery, four restricted-token denials and audit plaintext exclusion passed. The live key service, its keys and policies were untouched. This remains explicitly **single-host testnet recovery**. Independent backup availability and independent-host recovery are unqualified; mainnet was not deployed. Memberships, ordinary choices, authorization, financial amounts and transaction graphs remain public. Telos shielded payments remain a [separate disabled proposal](../proposals/2026-10-16-telos-evm-privacy.md).
