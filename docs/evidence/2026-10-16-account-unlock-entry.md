# Clear account-unlock entry

The user reported a locked Profile screen without an obvious action. A controlled check of the preceding deployed bundle confirmed its existing sign-in-only fallback could offer Access & recovery; the screenshot's exact revision was not established. This change makes the unlock entry explicit and brings the matching saved-vault password form directly into Profile.

The signed-in portal header offers **Unlock account** while keys are locked outside the Account page. It uses the existing safe account-return helper and opens Profile directly, including when a return destination would ordinarily select Access & recovery. Successful full-access paired sign-in returns to that destination only after keys unlock. The password form uses the existing account-checked unlock/sign-in method and also keeps its existing return behavior.

Only a matching saved encrypted vault gets **Password for this device**. Existing full-access paired sign-ins remain available. When no paired method has full access, the profile offers **Use another device** and **Use recovery kit**. The device action opens the existing recovery accordion and focuses its request button; it does not create a request. The kit action opens the existing restore dialog, retaining replacement acknowledgement and identity checks. A DAO approval wallet without full-access recovery cannot decrypt private-profile keys.
