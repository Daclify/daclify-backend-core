# Community MCP foundation — M1

Source implementation on the existing isolated `feat/self-service-mini-apps` branches. No deployment, real account deletion, native authority change or asset movement in this task.

Core owns strict connection/tool/preparation/submission schemas and the shared Node client. The bounded inputs preserve maximum uint64 strings and exclude private keys, arbitrary actions and payout fields. Login checks both public keys, exact origin/audience/challenge/expiry before root signing. Separate delegated signing is checked against current native context. Exact prepared objects are cached, immutable previews are rechecked, invalid delegate signatures rejected, and unknown deliveries freeze new preparations. The trusted SDK caller must persist packets; M2 supplies the durable local credential/delivery lifecycle.

Separate `packages/community-mcp` uses stable split MCP `@modelcontextprotocol/server`/`client` **2.3.1**, verified against the installed package API and [official SDK v2 documentation](https://ts.sdk.modelcontextprotocol.io/v2/). Core's restricted public runtime dependencies remain unchanged. Producer-owned public modules encode current policy, pinned deployment and independent review rules; Activity requires a separate app grant/configuration. Root/private profile/treasury/general signing tools are absent. The protected local signer revalidates the exact preparation; hosted tools do not include `submit_prepared`.

The existing F4 publish example now shares the core client authentication/transport rather than implementing another login protocol. The clean installation native regression consumes the current immutable public artifact.
