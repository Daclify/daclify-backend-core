# Daclify V2 Documentation

Start with the [master plan](superpowers/plans/2026-10-05-daclify-v2-master-plan.md), then the architecture, bounded work packages and evidence register linked there. The [release and test policy](superpowers/plans/2026-10-05-daclify-v2-release-docs-test-policy.md) makes generated reference material, explanatory user guides and version-aware in-product help part of feature acceptance.

These are planning documents. Generated API/ABI/configuration references and user/operator release bundles will be produced from the implemented canonical schemas and tested artifacts. No application documentation generator exists yet.

Core owns shared architecture, common protocol/operation guides and the tested cross-repository release manifest. Module producers own their behavior/configuration/trust guides and generated module references. Frontend owns product help presentation and user journeys, consuming matching reference bundles.
