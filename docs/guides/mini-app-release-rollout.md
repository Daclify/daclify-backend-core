Candidate: core **0.15.0-alpha.17**, modules SDK **0.10.0-alpha.24**, frontend **0.15.0-alpha.19**, MCP **0.1.0-alpha.6**, native modules **0.10.0-alpha.3**. Exact archives, migration hashes, resource measurements and actual checks are recorded in the adjacent evidence. Never replace a consumed archive or edit migrations 041–048.

## Qualification boundary

`npm run package:protocol` produces explicit development artifacts. A public qualified release requires `npm run package:release -- --evidence <bundle.json>` against clean, exact source refs. The validator requires every existing external check plus native permissions, account lifecycle/restore/key erasure, complete mini-app installation/journeys, privacy approval and actual harness evidence. Zero assertions, failed/skipped checks, missing suites, dirty source, changed reports or mismatched SDK/MCP/starter pins refuse qualification. A passed flag is not publication or deployment authorization.

The testnet single-host recovery report is version-bound and expires **17 October 2026 14:46:09 UTC**. The fresh alpha.17 TLS restore and configured-key roundtrip retain that deadline. Production needs independently available keys/exclusions and actual independent-host restore, approved controller/legal basis/retention/DPIA and remaining provider/wallet/client evidence. A ciphertext row or deleted login link does not establish anonymization or universal erasure. [Privacy assessment](../research/2026-10-12-on-chain-profile-privacy-assessment.md).

## Prepare the deployment packet

1. Fetch current `origin/dev` in core/modules/frontend; integrate current work without losing pending requests or UI changes. Pin three exact committed refs. For the standalone website, keep the reviewed promotion branch separate until its production release is authorized.
2. Create detached candidate checkouts from those refs, install their exact lockfiles and frozen archives (including `packages/community-mcp` before the core build), build and compare released public bytes. Copy the compiled `-O=s` native binaries and ABIs only after matching generated code/raw-ABI hashes. Do not use another checkout's uncommitted files or claim its dirty ref is clean.
3. Save an owner-only SQL dump, native WASM/raw ABI, primary table rows, balances, owner/active authorities, action links, configuration overrides and current frontend entry. Inventory pending outbox/native steps, claims, subscriptions, keys and exclusion journals. Preserve the former release for recovery; do not restore it over newer user actions.
4. Bind the development manifest/evidence to the exact refs and lock/build/archive/migration hashes. Keep unavailable public-release reports absent/held. Do not fabricate provider, independent operator, legal-policy or clean-machine evidence from local fixtures.

## Apply in dependency order

1. **Database and readers:** pause the testnet API during the incompatible native transition. Apply migrations 043–049 additively through the existing coordinator. Compare account identities, credentials, links, canonical ownership and historical migration hashes against the saved state. New erasure fields begin in `none`; migration does not delete an account.
2. **Key custody and recovery:** preserve the current transit key, database grants, independent-of-SQL exclusion journals and finite controlled backup horizon. Validate the fresh report against the actual configured frontend origin, storage scope and TLS key-service origin. Reapply deletion/revocation exclusions before opening restored access. Never select an old report because its filename exists.
3. **Native runtime:** verify the observed old code/ABI, round-trip every saved primary row through the new ABI and check available RAM using native code billing (on this testnet, ten times WASM growth plus raw ABI growth), action-link overhead and reserved headroom. Upgrade code/ABI and rebind an existing RAM observer atomically; preserve an absent observer unless a separate backfill is reviewed. Pin the observed Hub registration independently, then refresh its runtime hashes while preserving owner, metadata and listing. Repair only missing reviewed `execctx` links and narrow relay `operator` links, including operation-bound exit and permissionless expired-session cleanup. Owner/active authorities, user credentials and balances must remain unchanged.
4. **API:** start the exact candidate source. Read network/capability/DAO/account/resource endpoints; check current runtime/module pins and schema hashes. Preserve deliberate feature gates and typed failure states. Account erasure stays disabled until its real operator/provider/retention requirements are qualified.
5. **Frontend:** build against the new immutable vendor archives, including the newer Grants/Treasury/Documents/Members work. Publish immutable assets before replacing the public entry. Keep the prior entry/assets for rollback. Check desktop/mobile account entry, Mini apps, help/downloads, accessibility and console/API errors on the actual testnet origins.
6. **MCP and directory:** enable the reviewed testnet local connection and verified artifact downloads only with matching pins. Hosted HTTP additionally requires the exact approved client IDs/callbacks and genuine OAuth journey; unregistered/wildcard callbacks stay refused. Directory moderation reads the actual governing DAO; a verified origin is ownership evidence, not an endorsement. Perform any live qualification using disposable synthetic actors only, never a real user's erasure or DAO closure.
7. **Website:** publish reviewed static promotion only in its separately authorized environment. Copy and links must describe actual capability/deployment availability. Hosted mini-app database provisioning remains future work; current SQLite/PostgreSQL recipes are operator-owned.

## Verify and roll back safely

Wait for irreversible native blocks. Verify the new runtime/ABI/observer/Hub pins, preserved primary rows, account ownership/auth links, owner/active authorities and balances; record only hashes/counts publicly. Inspect actual API health and installed source/version before publishing the entry. The rollout packet contains transaction IDs, immutable artifact/source pins, saved configuration and public-browser checks.

On a service failure, first disable the affected capability and keep the compatible candidate API/readers available for reconciliation. Reconcile the original protected packet before signing another nonce/event. Reverting HTML/configuration is reversible; restoring old SQL or replaying old signed packets over new actions is not a rollback. Restore deletion/revocation exclusions before any access. Preserve unresolved claims, stake, liabilities, receipts, cleanup exclusions and key recovery even while features are unavailable.

A native downgrade requires a separately reviewed current-state/old-reader compatibility packet. Retained new-format rows, closures and erasure receipts must not be silently discarded. Keep the saved binary/ABI privately; their presence does not authorize an automatic downgrade or owner/active key replacement. A missing external qualification leaves public release held and is recorded as unrun.
